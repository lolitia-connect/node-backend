## 2. 同步落点已包含、当前继续保留的定制

这些行为不是 `cd8e1d9` 或 `55e8776` 新创造的功能，来源和适配细节见 [历史同步说明](./v1.1.5-to-v1.2.0.md) 及 [契约笔记](../panel-sync-notes.md)。

- **多协议实例：** 面板以 `type:id` 标识协议实例；节点 controller、面板 query、入站 tag、证书路径和流量/在线上报必须保留 `protocol_id`、`id`、`name`，不能按 `type` 去重。
- **配置格式协商：** Protobuf 用于用户和报告等接口；配置在检测到协议数组后切换 JSON，因为当前双方 `ServerProtocol` schema 没有实例 ID。不要为了“全部 Protobuf”删除 fallback。
- **证书与日志：** 保留 `/etc/PPanel-node/<protocol-id><server-id>.cer/.key` 命名、ACME/self/file 模式、组件级日志和 fork 的安装/release 来源。
- **Shadowsocks obfs：** `obfs`、`obfs_host`、`obfs_path` 是此 panel/node 的活动字段；上游移除 legacy obfs 的规则不能直接复制。
- **Mieru 独立数据面：** 保留 TCP/UDP、multiplex、UUID 认证、会话级流量计数、空用户恢复、撤销、准备式重载和共享流量重试；不要把它强行改成 Xray 普通入站。
- **兼容回退：** Xray controller 在 Prepare 的 alive 计数请求收到明确 HTTP 404/405 时选择本地设备限制；其他错误不是“不支持”。运行中的本地模式不会自动发现 panel 升级，须重新准备 controller。Mieru 不走此路径。
- **流量可靠性边界：** [trafficQueue](../../node/traffic.go)按 panel/鉴权/server/type/instance 隔离，跨重载保留未 ACK 数据，但仅在内存中；节点报告没有稳定的幂等请求 ID。不能把 backend 内部 replay marker 描述为 node HTTP 重发 exactly-once。
- **Fork 工程配置：** [安装脚本](../../scripts/install.sh)和[管理脚本](../../scripts/ppnode.sh)指向 `lolitia-connect/node-backend`；[日志](../../common/logx/logx.go)分 xray/mieru；Docker/CodeQL/release 工作流保留本地 Action 版本。它们是相对官方目标的存量差异，不全是这次同步新增。完整 34 路径索引列明具体版本与行为。
- **工具链边界：** [go.env](../../go.env)保留 `GOEXPERIMENT=jsonv2` 文本，但文件存在不意味着 Go 自动加载它；运行以实际 Go 环境和 [go.mod](../../go.mod) 为准。固定 Xray 的默认 MPTCP 禁用、REALITY 版本、TLS/SS/TUIC 行为见历史 S03–S05。

## 4. 当前 backend v1.21.7 契约对账

上轮检查按源码对比发现设备接口、NW3 格式和证书指纹接收已在 backend 实现；相应 node 路径原已存在。**这只是静态契约核对与 node 自身测试，不是连接真实 backend/Redis/客户端的端到端验收。** 本轮仅整理文档，没有追加业务实现。

### N01. 全局设备准入已由 panel 提供

当前 backend 的 [native_routes.go](../../../backend/internal/handler/native_routes.go) 注册：

- `GET /v1/server/alivelist`
- `POST /v1/server/device`
- `POST /v1/server/online`

节点 Xray controller 在 [node/controller.go](../../node/controller.go) 的 Prepare 探测 alive，成功时在 Start 安装 `ClaimDevice`；[node/task.go](../../node/task.go) 刷新计数和独立上报在线批次。alive 的 404/405 选择旧 panel 本地回退，其他错误仍失败。JSON 请求/响应分别是 `{uid,ip}`、`{allowed,ttl_seconds}`、`{alive}`、`{users:[{uid,ip}]}`，Protobuf 由相应消息编码。

这些路径的存在不证明当前运行节点自动切换到全局模式；已选择本地模式的 controller 需重新准备。Mieru C01 只调用 online，不安装 `ClaimDevice` 或 Xray limiter。

### N02. Nowhere 已从旧 shape 对账到 NW3

当前 backend 的 [nowhere.go](../../../backend/internal/model/node/nowhere.go) 将存储的 version 0/1 在投影时升级为 3，固定 `nw3` ALPN，并在 obfs 为空时默认 Morph（保留显式 `none`）；[用户列表](../../../backend/internal/logic/server/getServerUserListLogic.go)及 placeholder 通过 `ProtocolCredential` 把 UUID 转为 32 位小写十六进制 shared key。节点 [core/protocol/nowhere/config.go](../../core/protocol/nowhere/config.go)、[core/user.go](../../core/user.go)接受此格式，[api/panel/server.go](../../api/panel/server.go)走 `/v2/server/{id}`。这是读/投影兼容逻辑，不是本轮已执行的全库存储迁移。

旧的 `version=1`、`now/1`、连字符 UUID caveat 已过时；历史段落保留在 [panel-sync-notes.md](../panel-sync-notes.md) 供追溯，顶部 2026-11-19 对账优先。

### N03. 自签名证书指纹上报已接通

节点 [node/cert.go](../../node/cert.go) 计算 self leaf 指纹，由 [api/panel/panel.go](../../api/panel/panel.go) 附着到该 NodeClient 后续请求；backend 的 [status handler](../../../backend/internal/handler/server/serverPushStatusHandler.go) 读取 header，[status logic](../../../backend/internal/logic/server/serverPushStatusLogic.go)调用 `ApplyReportedCertPin`。这证明上报/接收路径存在，不代表每种请求都会保存 header。

backend 当前 [cert_pin.go](../../../backend/internal/model/node/cert_pin.go)按 server + protocol type 更新 self 实例，未使用 `protocol_id` 隔离上报 pin；不能因为 query 保留实例 ID 就宣称证书 pin 已逐实例隔离。`cert_pin_sha256` 服务于订阅客户端，不是当前 node config DTO 输入；这和配置 JSON fallback 是独立边界。

### N04. Protobuf fallback 仍必须保留

backend 与 node 的 `ServerProtocol` 定义当前字段逐项一致，但没有协议实例 ID，也没有 node config 使用的 `cert_pin_sha256` 字段。节点必须在配置响应含协议数组时记住 JSON 模式；用户列表和报告继续可以使用 Protobuf。

## 5. 协议能力与未移植项

| Panel 可能下发 | Node 当前状态 | 处理 |
| --- | --- | --- |
| `vmess`, `vless`, `trojan`, `shadowsocks`, `hysteria`, `hysteria2`, `tuic`, `anytls`, `mieru` | 已实现 | 保持当前 validate/build/controller 路径 |
| `nowhere` | 已实现 NW3 | 需要 v3、`nw3`、TLS 证书；走 `/v2` |
| `socks`, `http`, `naive` | node 不实现 | `IsSupportedProtocol` 跳过，不能宣称 panel 可保存就代表 node 可服务 |
| `shadowsocksr` | **仍未实现** | Xray-core 没有可直接复用的 SSR inbound；需要独立协议实现、auth_chain/obfs 处理和真实客户端验证 |
| `snell` | panel 当前不提供，node 不实现 | 不增加没有实际入口的死分支 |

### 真正未完成

- **ShadowsocksR inbound：** backend 已能标准化并投影 SSR，但 node 的 `IsSupportedProtocol`、`core/validate.go` 和 inbound builder 都没有 SSR。不要只把字符串加入 accept-list，否则会绕过校验却无法建立服务。
- **外部验证：** Linux root/nested `-race`、Unix 证书权限、静态构建、生产部署、真实 panel/Redis 多节点准入和 Rust NW3 客户端互通仍需专门环境。
- **上游后续同步：** `official-upstream/master` 当前不能替代明确 tag；下一次同步必须重新固定官方目标并审查 Xray/Nowhere/Protobuf 依赖。

## 7. 接手规则

1. 修改面板字段或协议前，先读 [panel-sync-notes.md](../panel-sync-notes.md) 和 backend 当前实现；不要只看官方 node 文档。
2. 修改 `Protocol`、Protobuf 或 panel API 时，先确认 `type:id`、JSON fallback、`protocol_id` 和旧 panel 404/405 回退仍成立。
3. 修改入站、证书或用户时，分别核对 `core/validate.go`、`core/inbound/`、`node/node.go`、`core/user.go` 和 limiter 生命周期；同类型多实例必须并行存在。
4. 修改 Mieru 时，保持它独立于 Xray，检查 session 级计数、online pending/traffic pending、ACK 和 Stop/Reload 路径。
5. 只把实际执行的测试写成通过；外部客户端、部署、跨平台 race 和真实数据库/Redis 证据不可由本地单元测试推断。
6. 新增或修改 AI 文档时，更新本目录入口和对应台账；不要把临时任务过程写回项目 README。
