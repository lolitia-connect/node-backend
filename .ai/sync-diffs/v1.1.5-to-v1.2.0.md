## 2. 同步时保留或补齐的 fork 适配

多实例、Mieru、日志和安装来源已有本地基础；配置 Protobuf fallback、准入回退及新的重载/计数适配在这次同步落点中补齐。它们不是同步后两次提交才新增，也不能全部说成同步前就已有：

- 面板协议实例用 `type:id` 区分，同一类型可以有多个入站；节点 controller、协议 tag、证书文件和流量/在线上报都必须保留 `protocol_id`。
- 面板配置没有协议实例 ID 的 Protobuf 字段，因此配置请求在收到协议数组时切换到 JSON；用户列表、在线用户、流量和状态上报仍可使用 Protobuf。
- Shadowsocks 的 `obfs`、`obfs_host`、`obfs_path` 是当前 panel/node 契约的一部分，不能照搬上游移除 legacy obfs 的规则。
- Mieru 是独立 controller，不能强行改成 Xray inbound；其 TCP/UDP、multiplex、UUID 用户、会话级流量统计、重载回滚和失败重试需要一起保留。
- 节点本地日志、证书命名、安装脚本、fork 的 Xray 和 Nowhere 来源必须保持可复现；不能用官方仓库路径覆盖本地发布约定。

## 3. 功能移植与适配

### S01. 面板 API 和 Protobuf 协商

入口：[api/panel/server.go](../../api/panel/server.go)、[api/panel/user.go](../../api/panel/user.go)、[api/panel/protobuf.go](../../api/panel/protobuf.go)、[api/server/v1/node_server.proto](../../api/server/v1/node_server.proto)。

- 增加 v2 server config 的 Protobuf 解码、用户/在线/流量/状态请求和响应编码，以及 JSON/Protobuf 内容类型检查。
- 配置使用 ETag/304；首次收到带协议的 Protobuf 配置时，因 schema 没有 `id/name`，节点记住 JSON 配置模式，避免同类型实例被合并或丢失。
- query 参数仍携带 `server_id`、`protocol`、`protocol_id`、`secret_key`；协议实例不能只由 `type` 表示。
- 404/405 只用于选择旧面板的本地设备限制；网络错误、鉴权错误、5xx、解码错误都保持失败，不得静默放行。

### S02. 全局设备准入与在线租约

入口：[api/panel/devices.go](../../api/panel/devices.go)、[limiter/device_admission.go](../../limiter/device_admission.go)、[limiter/devices.go](../../limiter/devices.go)、[node/controller.go](../../node/controller.go)。

- 新增 `/v1/server/alivelist` 计数读取和 `/v1/server/device` 原子准入回调，支持 JSON/Protobuf，并解析 `Retry-After`。
- 按订阅 ID + 来源 IP 共享设备租约；同一协议实例内的并发申请合并，限制等待者和面板并发，失败使用指数退避，明确拒绝不会被当作网络故障放行。
- panel 不支持时仅在准备阶段的 **alive 计数请求**明确返回 404/405 后选择本地设备限制；其余错误不等于不支持。此机制属于 Xray controller，不是 Mieru 的全局准入，也不会运行中自动探测 panel 升级。
- 全局模式安装 `SetDeviceAdmission(ClaimDevice)`；在线心跳、用户撤销和设备快照独立于流量上报，用户代际 fence 防止旧在途申请继续生效。

### S03. 证书生成、TLS 1.3 与 pin 上报

入口：[node/cert.go](../../node/cert.go)、[node/lego.go](../../node/lego.go)、[api/panel/panel.go](../../api/panel/panel.go)。

- 节点生成的自签名证书改为 ECDSA P-256，ACME 也使用 EC256；外部 file 证书不因此被改写。入站 TLS 的版本边界固定到 1.3，优先 X25519MLKEM768/X25519。
- 保留 `self`、`file`、ACME DNS/HTTP 模式和实例化证书文件名；证书轮换成功后重载。
- `self` 证书的 leaf DER 计算小写 SHA-256，并通过 `X-Node-Certificate-SHA256` 发送给面板；空值不发送。
- 出站 pin/`allow_insecure` 语义仍由面板适配层决定，节点不能把指纹上报误认为已完成面板客户端验证。

### S04. Nowhere NW3

入口：[core/protocol/nowhere/](../../core/protocol/nowhere/)、[pkg/nowhere/](../../pkg/nowhere/)、[core/inbound/build.go](../../core/inbound/build.go)、[core/user.go](../../core/user.go)。

- 导入官方 Nowhere 3.3.0 兼容实现，支持 TLS TCP、QUIC、Morph、认证表原子发布、流量计数、设备准入和用户撤销。
- 通过本地 Xray inbound 适配器复用 dispatcher；Nowhere 自己拥有 carrier listener，不走 Xray 固定传输的 JSON 协议名表。
- 明确要求 NW3、`nw3` ALPN、TLS 证书和 `mix|tcp|udp` 网络；旧 `now/1` 协议不兼容。
- panel 当前版本当时仍下发 version 1/`now/1`/连字符 UUID，因此 node 侧明确拒绝该形状。后续 panel 已升级为 NW3，现状见当前定制台账。
- 外部 Rust 客户端互通测试保留为显式环境变量 `NOWHERE_RUST_VECTOR_BINARY`，不把缺少外部二进制当作本地单元测试通过。

### S05. Xray、TUIC 与传输兼容

入口：[core/transport/tuic/](../../core/transport/tuic/)、[core/xray.go](../../core/xray.go)、[go.mod](../../go.mod)。

- 固定 fork Xray commit `e087e74a1bf2`，同步 Go 1.27.1、QUIC 和 protobuf；**Mieru v3.34.0 → v3.39.0 是本地同步适配，官方目标没有该独立 controller/依赖**。
- TUIC 使用新的原生 QUIC 传输，保留认证/首个请求并发兼容修复；TUIC 出站中继仍未实现。
- 关闭默认 MPTCP，保留旧 REALITY 客户端兼容和 SS2022 密钥校验；Freedom 出站私网规则按当前 Xray 行为处理。
- 同步时 README 曾记录固定 Xray 中 Hysteria2 UDP `closed` 访问竞态；本轮未复现或审计依赖源码，只保留该历史风险，不冒充新的 race 结果。
- Nowhere 协议模块的 DATAGRAM 分片上限不等于 Xray 数据面无损支持所有 UDP 大小：适配器丢弃空包，历史同步说明还记录 freedom 8 KiB 响应缓冲边界；TUIC 出站、远程 Egress 不应写成已实现。

### S06. 生命周期、流量与 Mieru

入口：[node/node.go](../../node/node.go)、[node/traffic.go](../../node/traffic.go)、[node/mieru.go](../../node/mieru.go)、[common/task/task.go](../../common/task/task.go)。

- 配置重载先准备新用户、证书和入站，失败时恢复旧配置；流量队列跨重载/协议移除保留并重试。
- Mieru 会话级统计替代进程级全局指标，避免多实例重复计费；空用户启动继续轮询，恢复后再启动监听，撤销用户关闭对应会话。
- `cd8e1d9` 在同步后补齐 Mieru 在线用户定时保活、批量上报和失败重试；上报成功只确认对应批次，避免并发连接在 ACK 前消失导致在线状态丢失。
- Mieru 是独立数据面，不经过 Xray 路由、限速或设备准入器；在线报告只补观测/租约刷新，并未实现 Mieru 全局配额控制。
- 流量 pending 只在内存中，HTTP 报告无 node 侧稳定幂等标识；退出未送达或崩溃可能丢失，响应丢失后重发可能重复计费，不承诺 exactly-once。
- 所有任务在 controller 关闭时停止；面板请求使用 context，避免重载/退出时留下后台请求。

## 4. 官方增量的处理边界

| 类别 | 决策 |
| --- | --- |
| Xray、QUIC、protobuf 和 Mieru 依赖 | 适配并固定 fork 版本，保留本地替换和安装来源 |
| 设备准入与在线租约 | 适配；旧面板保留 404/405 本地回退，其他错误失败关闭 |
| Nowhere NW3 | 适配；旧 panel 合约当时不兼容，后续 panel 对账已解决 |
| 证书指纹上报 | 适配；node 负责上报，panel 负责存储/分发语义 |
| 官方 Protobuf 配置 | 适配但保留 JSON fallback；未伪造实例 ID |
| Shadowsocks legacy obfs | 不照搬上游移除规则；本地 panel/node 仍使用这些字段 |
| ShadowsocksR | 未移植；Xray-core 没有可直接复用的 SSR inbound，需独立实现和真实客户端验证 |
| panel 数据库迁移 | 不适用；node 不拥有 backend 的数据库 schema/migration |
| 官方上游发布流程 | 只适配 fork 的 workflow、安装脚本和 Docker 入口，不覆盖本地发布来源 |
